# Design-reference verification

September 14, 2026. These results concern only the standalone browser mockup.
They do not pass any Unity, physical Quest, AI service, or learning-effectiveness gate.

## Automated checks

`verify-mockups.cjs` runs using Playwright and Node; the page itself needs neither
an installed package nor a server. Checks passed:

- All five views select and render; browser reports no uncaught page errors.
- Build accepts three fourths and gives repair feedback for two fourths.
- Equivalence keeps the physical endpoints equal at SVG x=604; a wrong expression
  does not change the board and can be repaired by independent field edits.
- Comparison exposes equal-parts, excess-above-half, and neutral-endpoint support
  from explicit local fixture choices; a correct operator with supported reason advances.
- Reset clears the reference state.
- No page-level horizontal overflow at widths 1440, 800, 390, and 320 pixels.
- Seven PNG references are regenerated by the check script.

## Visual inspection

Reviewed desktop arrival, build, equivalence, repair/benchmark, and departure
captures, plus the narrow review layout. Adjusted strap contrast and moved the
departure aircraft clear of the instruction panel. Fraction lanes retain identical
whole widths and proportional pieces. The mobile view is a scene overview with
readable notes and controls below, not a claim of mobile diagram readability.

## Deliberate limitations

No controller tracking, grabbing physics, full T01–T06 progression, recenter/height
controls, live inference, error-race simulation, audio/haptics, or animated aircraft
is implemented here. No child/user study was conducted. The form controls and
annotated scenery are reference material for subsequent Unity authoring.

This verification script is a mockup harness, **not** the planned game
`tools/verify.sh` harness. The latter still needs implementation.
